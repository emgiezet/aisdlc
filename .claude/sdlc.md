says so in `scope-report.md`. A spec may set its own `Change budget:` line under `## Scope` —
that wins, which is how a mechanical codemod gets a wider budget than a behaviour change.

## Test conventions

- **Test file naming:** `*_test.sh` (sourced by `tests/run-tests`), `*_test.mjs` (`node:test`),
  `tests/integration/*.sh`, `evals/harness/selftest.sh`
- **Test location:** a `tests/` tree per plugin; the runner's tests in `evals/harness/`
- **Use case ids in test names:** yes — every acceptance criterion's `UC-<n>` appears in the
  name of at least one test, so spec coverage is greppable. This is not optional.
- **Integration tests need:** `plugins/slop-guard/bin/slopguard doctor --install --all` for
  `make tool-integration`; Go 1.22 and Node 22 for `cd evals/fixtures/sandbox && make verify`

## Repo-wide out of bounds

Things an unattended run must never touch, whatever a spec says. Additive to each spec's own
`Out:` section.

- Generated files and lock files, unless the spec names them — here the generated slop-guard
  skills (the antipatterns skills and agent-discipline: regenerate with gen-skills, never edit
  by hand) and the pinned tools lock. Deliberately no backticked paths: scope-check would turn
  them into hard prohibitions, and every catalogue change regenerates those skills.
- CI configuration, unless the spec is about CI
- `version` fields in any manifest and `chore(release):` commits — the release workflow owns them
- `evals/fixtures/sandbox/**` — the eval fixture; changing it changes what every eval measures
- `.claude/retired-tests` — only a human retires a test
- `.worktrees/`, `.superpowers/` — local scratch

## Instruction hierarchy

This project uses the AI SDLC three-tier instruction hierarchy. Before any task:

1. Read `CLAUDE.md` — the Task Router table routes every task to exactly one playbook.
2. Find the row that matches your task and read **only** that `.claude/playbooks/` file.
3. Read the `.claude/rules/<stack>.md` file for every stack whose paths you will touch —
   Codex does not auto-attach path-scoped rules; open them explicitly.

Do not preload other playbooks or rules — loading everything degrades instruction following
and burns context you will need for the code.

## AI SDLC workflow

| Task | Codex command |
|------|---------------|
| Set up this repo for the pipeline (run once) | `$init` |
| Write a spec for a ticket | `$spec <TICKET>` |
| Build an approved spec unattended | `$implement <TICKET>` |
| Verify an implementation against its spec | `$qa <TICKET>` |
| Open a draft PR with the QA verdict | `$ship <TICKET>` |

The unattended queue (`aisdlc run`) is Claude-only and is not available in Codex.

# SDLC-001 — Multi-level planning and the skillify loop

## Problem

The pipeline has one planning artefact — the spec — and it states *what* must be observable,
never *how* the code will be shaped. `/sdlc:implement` therefore invents the program design
inside the build loop, under pressure to reach green, which is where the architectural hacks
come from: a `try/catch` that swallows the failing case, a cast that silences the type, a helper
dropped in the nearest file. The same pressure produces the second gap: every QA finding and
every `BLOCKED.md` is resolved once, in one branch, and teaches the next task nothing. The
harness has a place for compounding knowledge (`.claude/rules/`, `.claude/playbooks/`, the
router) and no step that ever writes to it.

## System context

| Component | Owns | Files |
|---|---|---|
| Commands | One phase of the pipeline, one instruction file each | `plugins/sdlc/commands/*.md` |
| Skills | The formats and floors the commands apply | `plugins/sdlc/skills/*/SKILL.md` |
| Queue runner | Worktree per task, phase loop, spec gate, cost record | `plugins/sdlc/bin/aisdlc` |
| Guards | Mechanical enforcement at `PreToolUse` and `Stop` | `plugins/sdlc/hooks/guard` |
| Eval harness | Scenario × model scoring against the sandbox fixture | `evals/harness/{run.sh,selftest.sh}` |
| Instruction hierarchy | Consumer repo's router, playbooks, path-scoped rules | generated by `/sdlc:init` |

Artefact chain today: `spec.md` → *(approval)* → code → `qa-report.md` → PR.

## Component boundaries

| Component | Exposes | Consumers |
|---|---|---|
| `/sdlc:arch` | `specs/<EPIC>/arch.md` — component boundaries + slice table | a human, then `/sdlc:spec` |
| `/sdlc:design` | `specs/<TICKET>/design.md` — signatures, call graph, build order, `files:` scope | `/sdlc:implement`, `/sdlc:qa`, eval scoring |
| `/sdlc:skillify` | Diffs into `.claude/rules/`, `.claude/playbooks/`, `CLAUDE.md` | every later task in that repo |
| `program-design` skill | Both artefact formats, sizing limits, anti-patterns | `/sdlc:arch`, `/sdlc:design` |
| `design` queue phase | `design.log`, committed `design.md` | `implement`, `qa`, `aisdlc logs` |

Artefact chain after this epic: `arch.md` → `spec.md` → *(approval)* → `design.md` → code →
`qa-report.md` → PR → `.claude/rules/`.

## Decisions

| Decision | Rejected alternative | Why |
|---|---|---|
| The spec stays the only human gate; `design.md` is agent-authored and committed | A second approval gate on the design | A gate makes the work unqueueable, which is the property the whole harness is built on |
| `design` is a queue phase, default-on, ahead of `implement` | Design folded into `/sdlc:implement` Phase 1 | A fresh context per phase is what stops the design from being bent to fit code already written |
| `files:` in the design's frontmatter is the declared file scope | A prose "File scope" section | Machine-checkable by the eval scorer and by QA with no parser |
| Scope growth is *recorded*, not forbidden — amend `files:` with a reason in the same commit | Hard-stop on any file outside `files:` | A hard stop turns every honest surprise into `BLOCKED`; a recorded amendment is visible to QA and to the reviewer |
| `/sdlc:arch` and `/sdlc:skillify` are interactive-only | Adding them to `ALL_PHASES` | `arch` is a decomposition decision a human owns; the queue's `settings.json` denies `Write(.claude/**)`, so a queued `skillify` would be blocked by its own permission set (`bin/aisdlc:139-140`) |
| Skillify knowledge extends the `task-router` skill | A fifth skill | `task-router` already owns the three tiers and the "When to add what" table; a second skill on the same subject is the duplication the skill itself forbids |
| No per-phase model or budget override | Add `--budget-design`, `--model-design` | The task record has one `model` and one `budget` (`bin/aisdlc:255-262`); a schema change is not justified before the design phase's cost is measured |

## Risks

- **Cost.** A fourth default phase raises `$/PR` from the measured `$0.59` baseline
  (`docs/ai-sdlc.md`). The design phase must stay a single document and no code; the number is
  unmeasured until `make harness-eval MODEL=haiku` runs, and the docs must say so rather than
  claim a saving.
- **A design a weak model ignores.** If `implement` treats `design.md` as background prose, the
  phase is pure cost. Mitigated by the mechanical hook: `files:` is compared against the diff by
  QA and by the scorer.
- **Skillify writing noise into the rules.** A rule harvested from a one-off defect makes every
  future task worse. Mitigated by the classification step and by refusing one-offs explicitly.

## Out of scope (epic-wide)

- Per-phase model/budget overrides in the task record.
- A GitHub-issue queue, `num_turns` handling, installer work — the other items in
  `docs/overlay-contract.md`.
- Any policy or organisation vocabulary: the overlay owns that, not this repository.
- Rewriting the existing scenarios' assertions; new keys are additive.
